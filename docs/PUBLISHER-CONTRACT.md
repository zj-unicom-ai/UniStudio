# 发布技能接入契约

项目根据实际文件路由平台，不根据平台名猜测操作。新增平台时，在 `skills/publish-<平台>/SKILL.md` 中提供可执行流程，并在 `skills/publishers.json` 登记唯一 ID、名称、别名、Skill 路径、支持动作和运行要求。当前仅随附 `wechat-channels`。

每个发布 Skill 应说明：

- 如何取得当前登录账号并与本机配置核对；依赖的浏览器、CLI、API 与登录方式。
- 输入：任务 ID、成片、封面、标题、描述、话题、可选合集/原创及排期；路径来自任务，不自行扫描最新 MP4 猜作品。
- 平台必要的规格与字段检查，以及实际上传、填表、提交、定时/草稿操作。
- 如何定位并核验本条结果，保存平台原文/截图和作品链接，区分草稿、排期、处理中和公开发布。
- 页面变化、登录失效、提交结果不明时如何停止与核验，不能重复提交碰运气。

共用生命周期：`ready → claim → 平台操作 → complete`。所有 CLI 与网页使用 `productions/state/tasks.db`，不要在 Skill 自建 JSON 队列或直接修改数据库。同一平台只允许一个进行中的发布会话；每个已领取任务最后应写入真实结果或 `needs_human`。

目标账号等本机参数追加到 `unistudio.local.json` 的 `publishers.<平台ID>`。示例配置只包含空账号和通用字段，凭据通过环境变量或运行器已有登录态提供。自然语言授权的范围按当次用户要求执行，不把制作需求当成发布授权，不重复索要已有授权。

每条任务目前对应一个发布目标。新增多平台分发能力时，应明确为每个目标建立独立记录/状态，不能用同一条任务的全局 published 冒充所有平台已发布。

贡献验证使用模拟平台或草稿预演，说明已验证范围；未经用户要求不向真实账号发测试作品。登记 Skill 并不等于自动安装其依赖或完成登录。
